# I4：F2 统一模型设置与审阅生命周期

日期：2026-10-29。实现留在工作区，由用户手动验收和 Git 提交。

## 已实现

- LiveModifyAction 使用项目 ProjectLlmService.modify，不再选择 .env 目录、不创建/关闭独立 HttpLlmClient。使用 Language model 的端点、模型、密钥及预算；没有配置时提示检查该设置和 Password Safe。
- 保留明确指令以及“发送完整单个 Java 文件，只有显式 Diff 批准才应用”的说明。Chat 不触发修改；不读取整个工程，不扩展多文件修改。
- 模型配置变化和项目释放会取消生成及已生成但尚在审阅的请求。审阅结束后的写回通过模型配置版本检查，拒绝过期建议。RAG 设置/资料变化不取消 F2、不关闭共享模型客户端。
- 请求取消传到生成任务；Diff 保留既有 100ms 取消检查。生成期限包含服务初始化和模型调用，使用项目配置加 5 秒启动余量；人工 Diff 审阅没有期限。
- 批准写回前再次核对项目/请求、路径真实位置、磁盘修改标记、文档身份/内容/修改标记及可写状态。同一文件的并发建议不能覆盖已应用的新版本；不同文件保留各自的请求边界。
- 取消与最终写回使用同一请求锁，模型配置检查先于请求锁，避免取消或配置失效穿过最终写入检查。取消完成之前已提交的写入视为已完成应用，不伪装为取消。
- 继续使用内置只读 Diff、WriteCommandAction、IDE 保存与 Undo。保存失败明确说明编辑器已改变、需要保存或撤销，只有保存成功才报告 APPLIED。
- 显式开发用 LlmConfigLoader/.env 示例仍保留，正式 IDE 入口不使用它们。

## 手动验收清单

1. 在 Language model 配置实际模型。对 examples/f2/SumDemo.java 的副本触发 Modify Java Code with LLM，要求修正减法错误：不再选择 .env；先出现内置 Diff，批准后文件保存，可 Ctrl+Z 撤销。
2. 用 GreetingDemo.java 副本要求方法重构；核对完整文件建议、批准后运行或编译。另起一次建议，取消/Escape/关闭 Diff，原文应保持不变。
3. 生成期间取消或关闭项目；切换 Language model 配置。旧任务不得弹出迟到审阅或应用旧建议。修改 RAG 设置不应误取消 F2。
4. 审阅期间修改文件，或先应用同一文件的另一份建议，再批准旧建议：应拒绝覆盖；只读/文件移走等情况也应明确失败。
5. 同时使用 Chat/F2，取消其中一个，另一个继续可用；生成超时/错误 Key 后可恢复。需要人工审阅多久都不应因模型超时而关闭 Diff。
