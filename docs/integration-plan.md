## 3. 组装原则与最小契约调整

```text
ChatPanel → RequestCoordinator → 项目级 ChatService 适配
                                  → LlmChatService
                                      → ProjectRagService.search
                                      → HttpLlmClient

回答 → 正文 + 默认可见来源摘要 + 可展开的已引用证据

显式 F2 Action → 快照/指令 → ValidatedModificationService
                            → LlmCodeGenerationService → HttpLlmClient
                            → 内置 Diff → 批准 → FileSnapshotWriter
```

- Chat UI 不自行执行第二次检索、不拼提示词。`LlmChatService` 已调用 `search(question, 5)`，保留这一唯一检索入口。
- `ChatAnswer` 当前只有 `SourceReference` 列表，没有原文。增加最小的不可变引用证据数据（如 `CitedEvidence`：chunk ID、SourceReference、text），兼容既有构造调用。不要把原文或分数硬塞进 SourceReference。
- `StructuredReplies` 校验模型引用后，从本次真实 evidence 筛出已引用片段；不接受模型编造的页码/原文，不在 UI 展开时重新搜索。若同一 reference ID 对应多个片段，保留其实际关联片段并按 chunk ID 去重。
- 首版详情只展示实际引用的证据，不把所有命中当成已引用内容；相似度分数无需进入正式回答。
- 项目级服务拥有 LLM 会话和客户端。Chat 与 F2 可以借用同一配置/客户端，但保留独立请求和取消边界。内容关闭只取消其请求，不关闭仍被其他入口使用的项目资源；项目关闭负责最终释放。

## 4. 执行阶段

### I1：统一 LLM 配置与项目服务组装

工作：

1. 增加项目级 Chat / code generation 模型设置：协议、端点、模型、超时、输出与输入预算，直接构造 `LlmConfig`。
2. LLM 密钥单独存入 Password Safe，与 Embedding 密钥隔离；不默认共用、不在 EDT 读取。留空保留、替换、清除及保存失败行为沿用 RAG 设置约定。
3. 增加项目级模型服务/会话，按需创建 `HttpLlmClient`、Chat 和 generator；未配置时显示可操作提示，保存设置不发起网络请求。
4. 正式 IDE 入口不隐式读取 `.env`、进程变量或要求选择配置目录；开发脚本可继续保留显式配置加载器。
5. 统一超时来源：LLM 总期限覆盖检索与生成；RequestCoordinator 的外层期限由同一配置派生并略晚于服务期限，避免配置超过 30 秒仍被旧固定上限截断。索引重建不套用聊天期限，人工 Diff 审阅不套用生成期限。
6. 配置切换取消旧会话任务并禁止旧结果回写；RAG 设置变化和资料/索引操作完成时，保守取消在途 Chat，下一次提问使用当前状态，不自动重新请求。已完成回答及其证据保留为当次快照。

预计涉及：`settings/`、`application/`、`plugin.xml`、RequestCoordinator 配置接入。

完成标准：多项目配置/凭据隔离；保存不调用 API；取消、重配、项目释放后资源和旧回调不残留。

### I2：接通 F0 真实问答

前置：I1 的配置及服务组装稳定。

1. 在 `CourseAiToolWindowFactory` 注入真实服务，使用非 Sample 的 ChatPanel；保留 Mock 作为测试替身。
2. 跑通资料登记 → 建库 → 加载 → Chat 检索 → LLM → 回答/来源，选中代码右键入口继续复用同一 Chat。
3. 正常空检索显示通用知识声明；未配置、未建库、损坏/不兼容索引、Embedding 失败均按失败处理，不假装无匹配，不调用后续模型。
4. 核对引用 ID、文档、PDF 页码/PPTX slide，以及请求 ID 与选区快照在整条链路中保持一致。
5. 保留清空取消、超时恢复、重复发送保护、隐藏保留会话、关闭释放及过期回调保护。

预计涉及：Tool Window factory、ChatPanel、项目服务及新的 F0 集成测试。

完成标准：本地可控 HTTP 的完整 Chat 链通过，有证据、无匹配、检索失败、模型失败及取消均能区分。

### I3：来源详情与产品页面收敛

1. 实施上述引用证据契约，并扩展 `StructuredReplies` 与 `ConversationView`。
2. 回答正文保留引用标记，末尾显示紧凑来源摘要；提供 `View details` / `Hide details`，按来源展示本次引用的可复制原文。
3. 无匹配回答展示声明，不渲染空来源卡；失败消息不展示伪引用。展开详情不调用 Embedding 或 LLM。

## 5. 验收矩阵

| 场景 | 通过标准 |
| --- | --- |
| PDF/PPTX 课程问题 | Chat 回答结合课件；默认可见文档与页码/slide；详情对应本次证据，人工核对引用语义 |
| 成功无匹配 | 无课程来源，清楚说明通用知识 |
| 检索故障 | 与无匹配区分，不继续调用模型；修复设置/索引后可再次提问 |
| 模型故障/伪引用/截断 | 安全报错，不展示伪来源或不完整建议 |
| 右键代码提问 | 仅本次选区及元数据到达模型，编辑器切换不改变已附快照 |
| 展开来源详情 | 使用回答自带证据快照，零额外网络请求 |
| 清空/取消/重配/关闭 | 在途任务终止，旧回复不污染新会话；隐藏窗口不丢会话 |
| 重启与多项目 | 配置及索引可加载，凭据与课程库互不串用；聊天历史仍仅内存保存 |
| F2 取消与批准 | 取消无写入；批准先经内置 Diff，成功保存后报告 APPLIED，可 Undo |
| F2 文件变化/只读/越界 | 明确拒绝写入，不覆盖用户新内容 |
| 最终界面 | Chat + Course materials，无独立 Retrieval preview，无生产样例入口 |
